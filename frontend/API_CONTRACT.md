# TablePulse API contract

Base URL `/api` (port 3000). JSON only. `date` = `YYYY-MM-DD`, `time` = `HH:MM`, both in the
restaurant's local time zone. Auth: `Authorization: Bearer <jwt>`.
Frontend reference implementation of every rule: `js/core/engine.js`, `js/core/api.mock.js`
and `js/core/validation.js`. Port that logic to Node (plain JavaScript).

## Error format (every non-2xx)
```json
{ "code": "SLOT_TAKEN", "message": "Human readable text", "fields": { "email": "optional per-field message" } }
```
| HTTP | code | when |
|---|---|---|
| 400 | VALIDATION | bad input (`fields` filled) |
| 401 | UNAUTHORIZED / INVALID_CREDENTIALS | no/expired token, wrong login |
| 403 | FORBIDDEN | wrong role or not your reservation |
| 404 | NOT_FOUND | table/reservation missing |
| 409 | EMAIL_TAKEN, SLOT_TAKEN, ALREADY_CANCELLED, ALREADY_STARTED | conflicts |
| 422 | TABLE_TOO_SMALL | table seats fewer than guests |

## Endpoints
| Method | Path | Auth | Body / query | Returns |
|---|---|---|---|---|
| GET | /config | none | | RestaurantConfig |
| POST | /auth/register | none | {name,email,password} | {user,token} (role always `customer`) |
| POST | /auth/login | none | {email,password} | {user,token} |
| GET | /auth/me | user | | User |
| GET | /availability | user | ?date&time&guests&pref | Recommendation[] (top 3) |
| POST | /reservations | user | CreateReservationInput | 201 Reservation |
| GET | /reservations/mine | user | | Reservation[] (own, newest first) |
| PATCH | /reservations/:id/cancel | user | | Reservation (owner or manager) |
| GET | /reservations | manager | ?date | Reservation[] (that day, by time) |
| GET | /floor | manager | ?date&time | FloorSlot[] |
| PATCH | /tables/:id/status | manager | {status: available\|occupied\|cleaning} | 204 |

## Shapes
```ts
User { id, name, email, role: 'customer'|'manager' }
RestaurantConfig { openTime:'11:00', closeTime:'23:00', slotMinutes:30, durationMinutes:120,
                   minLeadMinutes:30, maxPartySize /* largest table cap, computed */ }
Table { id, label, cap, zone: 'window'|'quiet'|'outdoor'|'centre' }
Recommendation { table: Table, match: number, reasons: string[] }
CreateReservationInput { tableId, name, email, phone, date, time, guests, pref, requests }
Reservation { id, code:'TP-XXXXXX', table: Table /*populated*/, name, email, phone, date, time,
              endTime /*time+duration*/, guests, pref, requests, status:'confirmed'|'cancelled',
              createdAt, cancelledAt? }
FloorSlot { table: Table, state:'available'|'reserved'|'occupied'|'cleaning', reservation: Reservation|null }
```
Map Mongo `_id` to `id` (schema `toJSON` transform). Never return `password`.

## Business rules (server must enforce, never trust the UI)
1. **Slots**: time must be one of `openTime .. closeTime-durationMinutes` step `slotMinutes`.
2. **Not in past**: date+time >= now + `minLeadMinutes`. Date >= today.
3. **Party size**: 1..maxPartySize. Table `cap >= guests`.
4. **No overlap**: same table + date, both `confirmed`, `newStart < oldEnd && newEnd > oldStart`.
   Back-to-back (21:00 after a 19:00-21:00 booking) is allowed. Cancelled bookings never block.
   Must be race-safe: use a unique index or a transaction so two simultaneous requests cannot both win.
   Suggested: store `startAt`/`endAt` Dates, plus a per-table-per-slot lock document with a unique index.
5. **Manual table status** (`occupied`/`cleaning`) matters only for TODAY and only for slots starting
   before `now + durationMinutes`. Never blocks other dates. `reserved` is derived, never stored.
6. **Cancel**: owner or manager. 409 `ALREADY_CANCELLED` if cancelled. 409 `ALREADY_STARTED` if start is past.
   Set `status='cancelled'`, `cancelledAt`. Do not delete the document.
7. **Roles**: set by server. Register always makes `customer`. Seed one manager. Hash passwords (bcrypt).
8. **Booking code**: generated by server, unique.
9. **FlowSense scoring** (see `js/core/engine.js`): capacity fit max 40, preference max 40, free-for-stay 20.
   Sort by match desc, then smaller capacity, then id. Return top 3.

## Suggested Mongo collections
`users` {name,email(unique,lowercase),passwordHash,role}
`tables` {label(unique),cap,zone,status:'available'|'occupied'|'cleaning'}
`reservations` {code(unique),table(ref),user(ref),name,email,phone,date,time,startAt,endAt,guests,pref,
requests,status,createdAt,cancelledAt}  index `{table:1,date:1,status:1}`
